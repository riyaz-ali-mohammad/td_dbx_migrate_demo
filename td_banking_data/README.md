# Synthetic data for the AML Transaction Monitoring batch

Input data for `../legacy_scripts`: 4 landing files, 19 seed tables, and the expected results to check a Teradata or migrated Databricks run against.

Everything is generated by `datagen/generate_aml_data.py` and is deterministic: the same `--seed` always gives byte-identical files.

**Fictitious:** every person, company, bank, BIC, sort code, IBAN and sanctions designation is made up. Any resemblance to real people or entities is coincidental. Country risk statuses (FATF / HMT / Basel) are illustrative, not the current official lists.

## Run date

| Item | Value |
|---|---|
| Business date (`BUSINESS_DT`) | **2026-11-25** |
| Transaction history | 2026-06-28 .. 2026-11-24 (150 days, needed for the 30 / 90 / 120-day rule look-backs) |
| Parties / accounts | 1,020 / 1,318 (RET 70%, BUS 18%, WLT 8%, CIB 4%) |

| History rows | 183,670 transactions; 99,959 account-day summaries |
| Sanctions list | 121 designations, 178 name rows (Russia, Iran, DPRK, Syria and Belarus regimes) |

## Folder layout


## Run order

1. Create the DDLs from `legacy_scripts/ddl`.
2. Load `seed/*.csv`.
3. Copy `landing/*` to the `../data/` folder the `.mld` scripts point at.
4. Run the 21 scripts in the README order:
   - `kycref.15` loads (REFSYS, KYCSYS, SANCSYS)
   - `kycref.35`, `.40`, `.50`, `.55`, `.60`
   - `dailytxn.02` to `.08`
   - `dailytxn.10`
   - `amlmon.15` to `.50`

On Databricks, the CSVs load directly with `read_files`. For example:

```sql
CREATE OR REPLACE TABLE aml_demo.db_ods.aml_txn_daily AS
SELECT * FROM read_files('/Volumes/aml_demo/raw/seed/DB_ODS.AML_TXN_DAILY.csv',
                         format => 'csv', header => true, inferSchema => true);
```

The fixed-width landing files can be parsed with `substring()` on `read_files(..., format => 'text')`. The positions are in the banner comments of `kycref.35`, `kycref.55` and `dailytxn.02`. Converting this parsing step is part of the migration demo.

The data-quality and load-control plants are listed in the `expected_dq_*` files:

| Area | Plants |
|---|---|
| Daily file | Placeholder account; unknown currency (XYZ); missing FX rate (KES); unknown country (QQ); unknown transaction type; closed sort code; unknown MCC; 2 duplicates within the file (FD); 3 re-sent history transactions (PD); a status change BK → RJ; a card reversal; 2 back-dated cheque postings |
| KYC file | DQ 101 (unknown primary party), 102 (PEP without EDD), 104 (unknown nationality), 106 (unknown product), 109 (UK company without a company number), plus about 3% random overdue KYC reviews (103) |
| REFSYS file | One unknown record type (`ZZ`) and one country record with an invalid date. Both go to `AML_REFSYS_REJ` |

All of these stay well below the 5% ERROR threshold, so `dailytxn.07` does not abort.

## Expected results (`expected/`)

| File | Content |
|---|---|
| `expected_alerts.csv` | 25 alerts for 2026-11-25. 22 come from the scenarios and 3 from background behaviour (2 business rapid-movement, 1 velocity); 1 has status SUPPR (S17) |
| `expected_screening_hits.csv` | 8 hits, broken down by name role (CP / OR / BE), match type (EXACT / TOKEN / BIC / CTRY) and sanctions group |
| `file_control_totals.csv` | Trailer record count and debit/credit totals per source system; they match the detail exactly (`RECON_STATUS_CD = 'OK'`) |
| `expected_dq_daily.csv`, `expected_dq_kyc.csv`, `expected_dq_refsys.csv` | Planted data-quality findings |
| `generation_stats.csv` | Volumes |

The expected alerts and hits are computed by a Python re-implementation of `amlmon.20` and `dailytxn.08`. It applies the same thresholds, segment → `ALL` fallback, look-back windows, reversal and rejected-status exclusions, and 30-day suppression. Use it as the reconciliation target when the converted pipeline runs. If a Teradata or Databricks result differs, compare it with the SQL first: the Python is an independent re-implementation, not the source of truth.

## Regenerating

```bash
python3 datagen/generate_aml_data.py --out .                       # defaults shown below
python3 datagen/generate_aml_data.py --out . --run-date 2026-11-25 --seed 42 --parties 1000 --history-days 150
```

`--parties 5000` gives about 900k history rows. Planted scenarios are always added on top of the background population, and their expected results move with `--run-date`.
